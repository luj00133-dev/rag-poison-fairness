THE ONE DECISION YOU HAVE TO MAKE

Does IP&M review double-anonymized? The Data and Code Availability section names a GitHub URL that
contains your username, and the manuscript carries your name, email and ORCID on its first page.

  * If review is SINGLE-anonymized (author known to reviewers): submit as is. Nothing to change.
  * If review is DOUBLE-anonymized: use the two files marked below instead, and delete the
    identifying front matter from the manuscript.

    manuscript_anonymized.docx   the manuscript with the repository URL replaced by
                                            "[anonymized repository]" and the title page stripped
                                            of name, email and ORCID
    title_page.docx                         already separate, so it can be withheld from reviewers
                                            and restored at acceptance

Elsevier journals usually state the review model on the journal's guide-for-authors page. If it is
not stated there, the safe default is to prepare the anonymized version, because submitting an
identifying manuscript to a double-anonymized venue gets it returned.


WHY THERE IS NOTHING ELSE TO UPLOAD

  * No separate figures or tables. All 7 figures and all 21 tables are inside the manuscript, and
    Editorial Manager builds the production files from it. Uploading them again is how a submission
    ends up with two versions of Figure 3.
  * No code archive. The Data and Code Availability statement points at the repository, which
    carries the implementation, the configurations and the scripts that regenerate every number.
    The supplementary zip deliberately does NOT duplicate the code; it carries the per-query result
    data and the raw model outputs, because those are what a reader cannot recreate -- the
    generation outputs would cost API calls to reproduce.
  * No graphical abstract. Not requested by the journal, and this paper's result is a table of
    invariances rather than an image.
  * No suggested reviewers. The cover letter states that none are supplied, to avoid a conflict of
    interest, and offers them on request. That is a defensible position and it is stated rather
    than left silent.


WHAT IS IN THE SUPPLEMENTARY ZIP, AND WHY IT IS THE ONLY OPTIONAL ITEM

  14 directories, 34 MB extracted, 2.1 MB zipped, plus README_SUPPLEMENTARY.txt.

  S1-S10   retrieval layer: per-query files for the controlled corpus, BBQ, six encoders and the
           three encoder-scale runs. These back Tables 2, 3, 4, 6, 8, 9, 15 and Figures 3, 4, 5, 6.
  S11-S12  generation layer: the model outputs behind the propagation result, including the answer
           text of every call.
  S13-S14  forced-choice probe: the measurements behind Tables 13 and 14 and Figure 7.

The README documents all three schemas separately, because the directories do not share one: the
retrieval files carry the R1/R2 metrics, the generation files carry per-group stance with the answer
text, and the forced-choice files carry a per-group two-alternative measurement. A reader looking
for drift_tv in a generation file will not find it, and should not.
